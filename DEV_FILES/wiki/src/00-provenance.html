0b. Stock vs custom: who wrote what

Much of what runs here is framework behaviour that is only configured in this repo. This page sorts every moving part into four buckets, so you know whose documentation to read and where a bug can possibly live.

BadgeMeaningWhere the code isRead
{{L}}Laravel framework or skeleton behaviour. We may have set a config value.vendor/laravel/frameworklaravel.com/docs
{{S}}A Statamic core feature used as shipped. Blueprint YAML and config/statamic/* count as Statamic configuration.vendor/statamic/cms; our YAML in resources/blueprints/statamic.dev

Custom code layered on a default gets two badges, for example {{C}} on {{S}}: a class of ours that extends or hooks into a framework feature. There you need both sets of docs.

Every tracked file

Generated by [[DEV_FILES/wiki/provenance.py]] from git ls-files. A file is stock when it is byte-identical to a fresh laravel/laravel or statamic/statamic install, edited when the same path exists there with different contents, published when it matches a file inside a package (a published config, migration or stub, sometimes reformatted by Pint), generated when a package's command wrote it, and custom otherwise.

"Edited" is not always a real change. Pint reformatted several published Statamic configs (import order, blank lines). git log -p on the file, or a diff against the stock copy, shows whether a value was actually changed. The values we did change are listed on the pages that use them.

How to tell, without this page

  • Namespace. App\… is ours. Illuminate\… is Laravel. Statamic\… is Statamic, including the Eloquent driver's Statamic\Eloquent\…. JothamLec\MarketingToolkit\… is the toolkit.
  • Routes. php artisan route:list --except-vendor lists ours (just POST csp-report); --only-vendor lists everyone else's.
  • Config. config/statamic/* and config/seo.php are a package's options with our values.
