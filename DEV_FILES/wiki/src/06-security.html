6. Security headers & CSP

The most custom part of the site. Every response gets security headers, an enforced Content-Security-Policy that can't break anything, and a strict report-only policy whose violations are collected and logged.

SecurityHeaders {{C}}

[[app/Http/Middleware/SecurityHeaders.php]] is appended to the global middleware in [[bootstrap/app.php]]. On every request it calls Vite::useCspNonce() (so @vite tags and the toolkit's inline scripts get the nonce), and on the way out it sets, unless a header is already present:

HeaderValue
Content-Security-Policy (enforced)frame-ancestors 'self'; object-src 'none'; base-uri 'self' + reporting
Content-Security-Policy-Report-OnlyThe full target policy: default-src 'self', scripts and styles by nonce, Google Tag Manager and Analytics allowed, 'unsafe-eval' for Alpine. Not sent on /cp.
Reporting-Endpointscsp-endpoint → route('csp.report')
OthersX-Frame-Options, X-Content-Type-Options, Referrer-Policy, Permissions-Policy, COOP, CORP; HSTS in production over HTTPS. X-Powered-By removed.

Collecting reports {{C}}

Browsers POST violations to /csp-report ([[app/Http/Controllers/CspReportController.php]]). The route ([[routes/web.php]]) strips session and CSRF middleware (a browser report has neither) and is throttled to 300 a minute. The controller accepts both report formats (application/csp-report and the Reporting API's list), drops browser-extension noise (chrome-extension: and friends), de-duplicates identical reports for 10 minutes and writes one JSON line each to the csp log channel (storage/logs/csp-*.log). Every knob is in [[config/csp.php]].

Subresource integrity {{C}} on {{L}}

[[vite-plugin-sri.js]] adds a SHA hash for every built file to the Vite manifest; Laravel's @vite prints it as integrity="…". A tampered asset on a CDN or disk then fails to load instead of running.

Why two policies? The enforced policy contains only directives that can't break the page. The strict one is report-only until the logs show it is clean on real traffic. Then it can be promoted. JSON-LD blocks (type="application/ld+json") have no nonce on purpose: browsers never execute data blocks, so CSP doesn't apply to them.

Caddy and these headers. The server's shared security_headers snippet sets its headers only if absent (?), so the application's CSP wins.
