10. Whiteboard defense

Questions you should be able to answer at a whiteboard after reading this wiki. Try each one before opening the answer.

Requests and routing

A visitor opens /technology. Trace every step to the page they end up on.

Caddy finds no file, so PHP runs. No app or toolkit route matches, so Statamic's catch-all looks for an entry with URI /technology, finds none and returns 404. On the way out the toolkit's HandleMissing matches the redirect rule (imported from database/seo/redirects.csv) and turns it into a 301 to /#how-it-works, counting a hit. The browser loads / and scrolls to the How It Works section.

Why did public/robots.txt have to be deleted?

Caddy serves existing files before PHP runs, and the toolkit doesn't even register its route when the file exists. The static file would have hidden the toolkit's robots.txt (with the /cp/ disallow and the Sitemap: line).

An editor creates an entry at /technology. What happens to the redirect?

The page wins: redirects only apply to requests that would otherwise 404. The rule stays in the table, unused, until the page is removed again.

Content

Where does the homepage's <title> come from, and why isn't it "Home"?

The home entry's seo.title, set by the import to "Verify Every Image. Eliminate Fraud." The toolkit would otherwise use the site name for the home page. No site name is appended to any title because SEO & brand's title_site_name is false.

Why does a deploy never overwrite a title an editor changed?

Deploys run pixaproof:import-content --once, which returns straight away when the pages collection exists. Only the first deploy imports.

Content is in SQLite, but the blueprint is a YAML file. Why the split?

The Eloquent driver is configured per repository. Content (entries, navigations, globals, asset meta) changes in the control panel and belongs with the backed-up database; blueprints define the structure, change with the code and are reviewed in git.

Security

Why does the site send two CSP headers?

The enforced one holds only directives that can't break a page (frame-ancestors, object-src, base-uri). The strict target policy is report-only; violations go to /csp-report and the csp log until the policy is clean enough to enforce.

Why don't the JSON-LD blocks need a nonce?

application/ld+json is a data block; browsers never execute it, so CSP's script rules don't apply.

Operations

Scheduled entries stopped going live. What do you check first?

The scheduler cron (deploy/server/etc/cron.d/pixaproof-laravel, installed by hand). Statamic's HandleEntrySchedule only runs from schedule:run.

A new server shows the default share image on every page instead of cards. Why?

config/seo.php enables cards only when PHP's imagick extension is loaded. Install php8.4-imagick and reload PHP-FPM; nothing else changes. (Home is unaffected either way: it uses the designed og-image.webp.)

A test passes alone but fails in the full suite. Where do you look?

State that outlives the transaction: files written outside the faked media disk, the Blueprint YAML written by seo:install, or a cache store that isn't per-test. The database itself is rolled back after every test.
