3. Content & SEO

Content lives in SQLite through Statamic's Eloquent driver; its shape lives in YAML blueprints in git. One command creates all of it. The Marketing Toolkit turns it into every SEO output the site has.

The import command

[[app/Console/Commands/ImportStatamicContent.php]] {{C}} on {{S}} (php artisan pixaproof:import-content) uses only Statamic's PHP API and the toolkit's own CSV importer (JothamLec\MarketingToolkit\Redirects\Csv::import()). It creates or updates, in order: the asset container and its two images, the collection, its entries and tree, the two navigations, the SEO & brand set (running seo:install), the SEO & brand values, and the redirects. It then checks the counts (3 pages, 2 navigations, 22 redirects) and fails if they are off.

  • Run again, it updates in place: same entry IDs, "0 created, 22 updated".
  • --once does nothing when the pages collection exists. Deploys and composer setup use this, so control panel edits are never overwritten.
  • DatabaseSeeder runs it, which is how the tests get their content.

Two Eloquent-driver bugs are worked around in the command. (1) Saving an asset container through $container->save() skips the repository's cache reset, so a null cached by an earlier lookup survives and Statamic's search indexer crashes; the command saves through AssetContainer::save($container). (2) A brand-new navigation tree is always stored empty (makeModelFromContract() writes [] when there is no model yet); the command saves the tree once empty, as the control panel does, then adds the items. Both are worth reporting upstream.

SEO output

All of it comes from the Marketing Toolkit {{A:Toolkit}}. The layout's <s:seo:head /> prints, in this order: the tracking tags (GA4 from SEO & brand, GTM from SEO_GTM_ID; production only), the meta tags, then the icon links.

Our two changes to the toolkit's defaults ([[config/seo.php]])

  • description.length 155 → 160, matching SEO & brand's field limit, so hand-written descriptions aren't cut.
  • og.enabled → extension_loaded('imagick'). Generated share cards need PHP's imagick (installed on production); a machine without it falls back to the default image. Home overrides its card with the designed og-image.webp (its entry's seo.image); Contact and Privacy get cards in the SEO & brand colours (og_accent, og_text, og_background).
