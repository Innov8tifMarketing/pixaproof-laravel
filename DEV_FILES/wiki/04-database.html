4. Database

One SQLite file holds everything that changes at runtime. Locally it is database/database.sqlite; in production it is shared/data/sqlite/database.sqlite, outside the releases so deploys never replace it.

Tables, by owner

TablesOriginHolds
users, password_reset_tokens, sessions, cache, cache_locks, jobs, job_batches, failed_jobsLaravelSkeleton tables. cache is the production cache store (the toolkit needs a serialising store)
users columns super, avatar, preferences, last_login, two-factor columns; role_user, group_user, password_activation_tokens, webauthnStatamicStatamic database users (control panel logins)
entries, collections, trees, navigations, global_sets, global_set_variables, asset_containers, assets_meta, addon_settingsAddon: eloquent-driverStatamic content. trees holds both the collection tree and the navigation trees
seo_redirects, seo_404s, seo_reports, seo_report_pages, seo_search_statsAddon: ToolkitRedirect rules and hits, the 404 log, site reports, Search Console numbers

Which Statamic repositories use the database and which stay flat-file is set per repository in config/statamic/eloquent-driver.php: blueprints, fieldsets, forms, revisions, taxonomies, terms, tokens and sites stay on file.

Why the Eloquent driver on SQLite, when Statamic's default is flat files? Production already ran on one SQLite file with tested backups (before every migration, and offsite to Backblaze B2). Keeping content there means one thing to back up and restore, and CP edits never conflict with a deploy's git checkout. The toolkit also recommends addon_settings in the database for the same reason.

Migrations worth knowing

  • The eloquent-driver's migrations (2024_03_07_*, 2025_07_07_*) are published copies Addon.
  • database/migrations/2026_10_06_143105_statamic_auth_tables.php and database/migrations/2026_10_06_143033_statamic_webauthn_table.php Statamic. statamic:install and php please auth:migration both publish two-factor and webauthn migrations; the duplicates were deleted so a single migrate works.
  • The toolkit's migrations run from vendor/ (not published).
  • database/migrations/2026_10_06_152703_drop_leads_table.php Custom drops the contact form's old leads table (empty in production). Its down() recreates the final schema.
