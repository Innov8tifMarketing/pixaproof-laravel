7. Commands, queue, scheduler

There is little background work. Most of it comes from Statamic and the toolkit, and it needs two things running on the server: the queue worker and the scheduler cron.

Commands you will run

CommandOriginWhat for
php artisan pixaproof:import-content [--once]CustomCreate or refresh the content (page 3)
php please make:userStatamicA control panel login
php please stache:warm / stache:clearStatamicStatamic's flat-file index (blueprints). Deploys warm it
php please seo:reportAddon: ToolkitA site report with a score (Pro)
php please seo:install --fieldsAddon: ToolkitAdd fields a newer toolkit version brings to SEO & brand

There is no csp:summary. The docblock in config/csp.php says to aggregate reports with php artisan csp:summary, but no such command exists in this repo. Read storage/logs/csp-*.log directly (one JSON object per line, with a fingerprint per directive, origin and path).

Queue

The queue is Laravel's database driver Laravel, run in production by the Supervisor program pixaproof-prod-worker (as www-data, like PHP-FPM; reference copy deploy/server/etc/supervisor/conf.d/pixaproof-prod-worker.conf), which every deploy restarts (queue:restart in deploy.php). Until 2026-10-07 the site had no worker; nothing was queued before Statamic. Statamic queues some listeners, including updating its search index when an entry is saved. In tests the queue is sync, so those listeners run inline. That is how the Eloquent-driver cache bug in page 3 surfaced.
