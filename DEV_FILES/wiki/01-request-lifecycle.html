1. A request, end to end

Every URL takes one of five paths: a static file, our single app route, a toolkit route, the control panel, or Statamic's catch-all that finds an entry. Knowing which path a URL takes tells you where to look when it misbehaves.

Step by step

  1. Caddy terminates TLS. If the path is a real file under public/ (built assets, media/, videos/, images) it serves it and PHP never runs. That is why the old public/robots.txt and favicons had to be deleted: while they existed, the toolkit's routes for those paths were never reached. See deploy/server/home/deployer/pixaproof-laravel/Caddyfile.
  2. Laravel boots from bootstrap/app.php Laravel. The only change from the skeleton is $middleware->append(SecurityHeaders::class) Custom, which adds the CSP and other headers to every response on the way out (page 6).
  3. The router tries routes in registration order: ours (routes/web.php, only POST /csp-report), Laravel's /up, the packages' routes, and Statamic's catch-all {segments?} last.
  4. Toolkit routes Addon: Toolkit answer /sitemap.xml, /robots.txt, /llms.txt, /favicon.ico, /apple-touch-icon.png, /icon-192.png, /icon-512.png and /site.webmanifest, without a session or cookies so they cache well.
  5. The catch-all Statamic looks the URI up in the entries table (/ is the root entry of the structured pages collection, /contact and /privacy its children) and renders the entry's template.
  6. Nothing found? Statamic returns a 404. On the way out the toolkit's HandleMissing middleware Addon: Toolkit checks the redirect rules: a match becomes a 301 (that is how /technology reaches /#how-it-works); otherwise the 404 is counted in the 404 log and errors/404.blade.php renders.

Redirects only answer GET and HEAD, and only for URLs that would 404. The old Route::redirect lines answered any method and took priority over pages. With the toolkit, a page always wins over a rule, so a page that comes back takes its address back automatically. A POST /technology is a plain 404. This was an intended change, and a test covers it.

Why can the catch-all be "last"? Laravel matches routes in the order they were registered, and Statamic registers {segments?} after the application's own routes. Any route in routes/web.php therefore beats an entry with the same URI. That is also how Phase A ran safely: the old Route::view pages kept answering while the entries were being built.
